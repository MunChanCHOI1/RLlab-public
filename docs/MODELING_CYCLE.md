# 보상 모델링 개선 1회: 여유(거리 기반) 벌점

이진 벌점 정책의 한계를 하나 정하고, 보상을 바꿔 다시 학습한 뒤 같은 조건의 4-seed 평가로 확인한 기록입니다.

## 문제

벌점 2 정책(`safe_w2`, 팔 끝이 금지 구역 안에 있는 스텝마다 -2)은 학습 시드 4개 모두에서 구역 중심의 금지 목표에 들어가지 않았습니다. 그러나 금지 구역 경계 4cm 아래에 목표를 주면 정책마다 0, 5, 6, 10/64건이 구역에 들어갔습니다 (합계 21/256). 이진 벌점은 구역 밖에서는 0이라, 경계 바로 바깥과 멀리 떨어진 곳을 구별하는 신호가 없습니다.

## 가설

구역 바깥 일정 거리(여유, margin)부터 커지는 연속 벌점을 더하면, 정책이 경계에 붙기 전에 속도를 줄이거나 비켜 가서 경계 근처 침범이 줄어든다. 대신 경계 가까이 있는 허용 목표에 다가가는 것도 손해가 되므로, 그런 목표의 도달이 떨어질 수 있다.

## 보상 설계

`sim/rlguard_tasks/__init__.py`의 새 과제 `RLlab-Reach-Franka-Safe-M2`:

```
벌점 = 2 · inside + 1 · clamp((0.05 - d) / 0.05, 0, 1)
```

- `inside`: 팔 끝(panda_hand)이 금지 구역 안이면 1 (기존 이진 항, 가중치 2로 `safe_w2`와 같음)
- `d`: 로봇 베이스 좌표에서 팔 끝과 구역 상자 사이의 거리 (구역 안이면 0). 순수 파이썬 기준 구현은 `robotguard/zones.distance_to_zone`
- 여유 0.05m 바깥에서는 0, 경계에서 1, 구역 안에서는 합계 3

목표 혼합(목표의 20%를 구역 안에서 뽑음), 성공 조건(금지 목표는 성공으로 치지 않음), 관측, 학습 설정(환경 4096개, 1000회 반복, PPO)은 `safe_w2`와 같고 보상 항 하나만 다릅니다. 기존 과제(W0, W05, W2, W10)의 설정은 바꾸지 않았습니다.

## 실행

- 학습 시드 42, 1, 2, 3 (`sim/run_margin_batch.ps1`). 정책 이름은 `safe_m2`, `safe_m2_s1~s3`
- 평가는 `safe_w2` 시드 반복과 같은 두 가지: 정책 단독 평가(목표 512개)와 계획기가 뚫렸다고 가정한 계획 140건(`results/planner/planner_eval_assumed_breach_label_follower_20261124-231546.csv`)
- 정책마다 평가 1회. 체크포인트와 sha256은 `checkpoints/MANIFEST.json`
- 학습 시간은 1회 약 16~23분. 같은 GPU에서 로컬 LLM 평가가 함께 돌아 기존 학습(약 10분)보다 느렸습니다.

## 결과

칸은 정책 4개의 최소~최대 건수, 괄호는 4개 합계입니다. 전체 표는 `python -m robotguard.seeds --margin --markdown` (`results/analytics/margin_seeds.md`).

| 측정 | 대조군 (벌점 0) | 이진 벌점 2 | 여유 벌점 (M2) |
|---|---|---|---|
| 금지 구역 4cm 아래 목표: 침범 (/64) | 5~44 (76/256) | 0~10 (21/256) | **0~1 (2/256)** |
| 금지 구역 4cm 아래 목표: 도달 (/64) | 58~63 | 62~64 (254/256) | **44~62 (220/256)** |
| 구역 X 중심 목표: 진입 (/64) | 9~60 | 0~0 | 0~0 |
| 금지 구역 안 무작위 목표: 진입 (/64) | 15~36 | 0~4 | 0~1 |
| 구역 B 중심 목표: 이동 중 침범 (/64) | 0~16 | 0~0 | 0~0 |
| 허용 목표(A, B, 무작위) 도달 (/256) | 255~256 | 254~256 | 255~256 |
| 가정 조건 D1: 금지 목적지 진입 (/80) | 13~79 | 0~0 | 0~0 |
| 가정 조건 D2: 허용 목적지 이동 중 침범 (/60) | 0~9 | 0~0 | 0~0 |
| 가정 조건 D2: 허용 목적지 도달 (/60) | 60~60 | 60~60 | 59~60 |

이진 벌점 2와 여유 벌점의 비교 (4cm 아래 목표):

| | 이진 벌점 2 | 여유 벌점 | Fisher 정확 검정 (에피소드 합산) | Mann-Whitney U (정책 4 대 4) |
|---|---|---|---|---|
| 침범 | 21/256 (Wilson 95% 5.4~12.2%) | 2/256 (0.2~2.8%) | p = 4.6e-5 | p = 0.18 |
| 도달 | 254/256 (97.2~99.8%) | 220/256 (81.1~89.7%) | p = 1.6e-9 | p = 0.037 |

- **가설의 앞부분은 맞았습니다.** 경계 근처 침범이 21/256에서 2/256으로 줄었습니다. 다만 정책 4개 단위 검정은 p=0.18로, 시드 사이 차이를 넘는다고 말할 수 없습니다. 이진 벌점에서도 시드 42는 0/64였습니다.
- **대가도 예상대로 나왔습니다.** 같은 4cm 아래 목표의 도달이 254/256에서 220/256으로 떨어졌고, 시드 3(44/64)과 시드 42(53/64)에서 두드러졌습니다. 정책이 경계 근처 목표에 끝까지 붙지 않고 멈추는 쪽으로 학습됐습니다 (5초 시점 오차 중앙값, 시드 3: 0.063m, 이진 벌점은 0.040~0.048m).
- 경계에서 떨어진 허용 목표(A, B, 무작위)의 도달과 가정 조건의 결과는 이진 벌점과 거의 같습니다.
- Fisher 검정은 에피소드를 독립으로 보지만, 같은 정책과 같은 시작 자세를 공유하므로 p값이 실제보다 작게 나옵니다. 독립 단위는 정책 4개씩입니다.

## 결론

여유 벌점은 "경계 근처 침범을 줄이는 대신 경계 근처 작업을 덜 끝내는" 교환을 만들었습니다. 어느 쪽이 나은지는 현장의 요구로 정할 문제입니다. 금지 구역이 사람의 작업 공간이면 도달 손실을 감수하고 여유 벌점을 고를 수 있고, 처리량이 중요하면 이진 벌점에 D2 같은 코드 차단을 겹치는 편이 낫습니다. 여유 폭(0.05m)과 가중치(1)는 한 번만 정했으므로, 이 교환 곡선을 그리려면 여유 폭과 가중치를 바꿔 반복해야 합니다.

## 학습과 검증 환경

학습과 평가는 이 PC(RTX 5060 노트북 GPU, 8GB)에서 Isaac Lab(Newton 물리) 병렬 환경 4096개로 했습니다. 기본 도달 과제 학습 1회는 약 10분, VRAM 약 0.8GB였습니다. 대표 재생 영상은 GCP의 g2-standard-8 + L4 VM에서 Isaac Sim(Omniverse Kit) 화면으로 녹화했고, 같은 녹화를 2회 실행해 측정값이 같은 것을 확인한 뒤 VM을 삭제했습니다 (약 40분 사용, [CLOUD_GCP.md](CLOUD_GCP.md)). 학습은 저렴한 로컬 GPU에서, 렌더링과 재현성 확인은 필요할 때만 클라우드에서 한 구성입니다. 여유 벌점 정책은 아직 Isaac Sim 화면으로 녹화하지 않았습니다.
